# 经验沉淀 (Lessons)

- [触发条件] Maya中查询空组或无子级的节点层级 -> [根因] `cmds.listRelatives(node)` 在无子级时会返回 `None` 而不是空列表，导致 `for x in None:` 抛出 `TypeError: 'NoneType' object is not iterable` -> [正确方案] 必须使用 `cmds.listRelatives(node) or []` 进行默认值兜底 -> [避坑规则] 所有 Maya 列表查询API（`ls`, `listRelatives`, `listConnections`, `listHistory` 等）在迭代前必须显式加上 `or []`。
- [触发条件] UI搜索框输入为空时构建查询列表 -> [根因] 直接使用 `"".split(",")` 会返回包含一个空字符串的列表 `[""]`，导致后续逻辑（如 `cmds.ls`）无法按预期判断“列表是否为空” -> [正确方案] `text.split(",") if text else []` -> [避坑规则] 分割用户输入前必须先判空，确保空输入能转换为真正的空列表 `[]` 进行阻断。
- [触发条件] 基于矩阵节点 (ComposeMatrix, AngleBetween 等) 的输出计算骨骼角度是否发生了变化 -> [根因] 即使处于默认姿态，经过多次矩阵乘法和反三角函数计算后，仍然会产生大约 `0.00001` 到 `0.001` 等级的极细微浮点数噪音，如果判断阈值设置过低，会把全身上下所有的骨骼都误判为"已旋转活动"状态，从而导致工具重置失败 -> [正确方案] 在检测骨骼实际发生活动时，将阈值提高到 `0.5` 到 `1.0` 等级的稳定数字（实际动画师制作 Pose 不会在乎这不到 1 度的角度）-> [避坑规则] 将骨架活动侦测阈值从传统的 `0.00001` 上调至至少 `0.5`，彻底免疫浮点数噪音带来的干扰。
- [触发条件] 含 RBF 辅助骨骼的绑定系统使用 ADPose 自动侦测姿势 -> [根因] RBF 辅助骨骼（如 `Shoulder_L_RBF_01~04`）的控制器被 RBF 解算器驱动，自身旋转值 > 0.5。如果把它们的控制器旋转也纳入活动检测，会导致 `len(ads) > 1` 并触发 `can not find pose` -> [正确方案] 对于已含 `angle` 属性的骨骼（已被 ADPose 管理），**仅**检测其 `.angle` 值，不再 fallback 到控制器 `.r` 旋转 -> [避坑规则] 永远以 `angle` 属性作为 ADPose 骨骼的唯一活动判据，杜绝 RBF/辅助骨骼控制器旋转值的干扰。
- [触发条件] `find_ctrl_by_joint` 返回 `None` 后直接拼接字符串 -> [根因] `twist.py` 的 `all_to_zero()` 中写了 `if joint:` 做空值守卫，但实际要检查的是 `ctrl` 而非 `joint`，导致 `ctrl` 为 `None` 时 `cmds.getAttr(None + ".rotate")` 抛 TypeError -> [正确方案] 改为 `if ctrl:` -> [避坑规则] 空值守卫必须检查**实际可能为空的变量**，而非循环变量。
- [触发条件] `cmds.ls("FKIK*_R", "FKIK*_L")` 用于定位 FKIK 控制器 -> [根因] 通配符 `FKIK*` 匹配到了大量内部节点（Condition, UnitConversion, setRange, MM 等共 84 个），每个都要执行一次 `attributeQuery`，造成无意义的性能开销 -> [正确方案] 改为精确列举控制器名称 `FKIKArm_R, FKIKLeg_L` 等 -> [避坑规则] `cmds.ls` 通配符必须尽可能精确，避免匹配到内部工具节点。
- [触发条件] 镜像已保存的姿态目标 -> [根因] 只镜像目标名称和 BlendShape、不复制控制器 `_poseMatrix`，会让目标侧退回角度反推，导致满姿态驱动不足并串起相邻方向 -> [正确方案] 将源目标的精确局部矩阵复制到目标侧，再用目标骨骼真实输出验证方向语义 -> [避坑规则] 镜像必须同时迁移姿态元数据，不能把名称相同当作姿态相同。
- [触发条件] Shoulder 与 Scapula 使用同一套左右镜像符号 -> [根因] 两类控制器的物理镜像都使用相同局部矩阵，但 Scapula 左右骨骼的方向坐标相反；反转控制矩阵虽能凑对方向数字，却会把整条手臂摆错 -> [正确方案] 控制矩阵按真实骨骼位置决定，方向标签按目标骨骼输出单独归一 -> [避坑规则] 先验证骨骼姿态是否镜像，再验证驱动值；不得用驱动数字反推控制器镜像规则。
